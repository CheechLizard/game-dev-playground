# game-dev-playground

LÖVE 11.x playground: a shared framework (schema-driven in-game editor, config
profiles, perf overlay, debug-draw layers) plus one game, horde-survivor, and
two inspection levels.

Read [README.md](README.md) for how it works, [HANDOFF.md](HANDOFF.md) for why
it is the way it is, and [docs/glossary.md](docs/glossary.md) for the
vocabulary. This file is only the things that are easy to get wrong.

## The core design constraint

**The schema is the single source of truth for every tunable.** The editor UI,
the config defaults and profile serialisation are all generated from it. Add a
setting to the schema and it appears everywhere; delete it and it vanishes from
the editor and is pruned from profiles.

Never add a second list of settings anywhere. Settings derived from content
(per enemy, per weapon, per passive) are generated by walking `content.lua` —
extend the content table, not the schema, for those.

`shared/framework/schema.lua` is therefore the file every feature touches. It
is the main merge-conflict hotspot when branches run in parallel.

## Commands

```bash
love .                       # run — from the repo root, never a subdirectory
luajit tools/test.lua        # 98 tests, ~5s
luajit tools/balance.lua --runs 6
```

**`love .` only works from the repo root.** `love games/horde-survivor` fails:
profiles are written with plain `io.open` relative to the working directory, so
they only land in `config/profiles/` when the root is the cwd.

**Use `luajit`, not `lua5.1`.** Homebrew dropped the `lua@5.1` formula. LuaJIT
is 5.1-compatible and is the VM LÖVE itself runs.

Treat `tools/balance.lua` as a *relative* signal between two runs of the
harness, not an absolute difficulty rating. It sweeps the pilot's bubble by
default and prints a row per bubble: read the spread, not one row. Survival
time, which weapon leads on damage and which enemy is the top threat all move
with the bubble, so a change that improves a single row has not actually
changed the balance.

## Keys

`F1` editor · `F2` perf · `F3` colliders · `F4` overlays · `F5` zoo · `F6` range
· `P` pause · `R` restart · `,` `.` cycle in the inspection levels.

## Conventions

- **No help text on the play surface.** Keys are documented in the README
  rather than drawn over the game. (The editor keeps its own key legend.)
- **No image files.** All art is drawn from primitives, including the
  placeholder weapon and passive icons. Keep it that way.
- **Keep the glossary in sync in the same change.** Adding, renaming or
  retiring a term means editing `docs/glossary.md` in that same commit.

## Parallel work

Worktrees live as *siblings* of the repo, never inside it — `love .` treats the
whole directory tree as the game source, so a nested worktree gets scanned and
packaged. `tools/worktree.sh <branch>` creates one at the right path.

Each worktree gets its own `config/profiles/` (written relative to cwd) and its
own LÖVE save directory (`conf.lua` derives `t.identity` from the checkout
directory name), so screenshot captures from parallel agents do not collide.

Conflict hotspots: `shared/framework/schema.lua` (let one branch at a time own
schema additions) and `config/profiles/*.json` (regenerable — take either side
and re-run rather than hand-merging).
